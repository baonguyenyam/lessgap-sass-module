# Database (Prisma + PostgreSQL)

Applies to `prisma/`, `src/lib/prisma.ts` and any code that queries.

- Use the single client from `@/lib/prisma`. Never `new PrismaClient()` elsewhere.
- Change the schema only in `prisma/schema.prisma`, then create a migration:
  `npx prisma migrate dev --name <what_changed>`. Commit the schema and the
  migration together.
- Never edit or delete a migration that has been committed. Fix forward with a
  new one.
- `src/generated/migrations.ts` is generated by `npm run build` (prebuild). Do not
  hand-edit it.
- A migration that could lose data (dropping a column, narrowing a type, adding
  `NOT NULL` without a default) needs an explicit note to the user and a data
  step in the migration. Ask before writing one.
- Every query on user-owned data is scoped to the owner (`where: { userId: user.id }`)
  or checked after loading. An id from the client is a claim, not a fact.
- Select only what you use (`select`) on hot paths and lists; paginate lists.
- Multiple writes that must succeed together go in `prisma.$transaction`.
- No raw SQL unless Prisma cannot express it; if needed, use tagged
  `$queryRaw` (parameterised), never `$queryRawUnsafe` with interpolated input.
- No database access in unit tests. Keep the logic in a pure function and test that.
