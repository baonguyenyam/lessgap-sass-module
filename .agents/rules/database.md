# Database (Prisma + PostgreSQL)

Applies to `prisma/`, `src/lib/prisma.ts`, `src/platform/db.ts`, `scripts/backfills/`
and any code that queries. Full standard: `spec/12-migrations-and-data.md`.

- Use the single kit client from `@/lib/prisma` in kit code, `tenantDb(ctx)` in
  module code, and the platform client only inside `src/platform/`. Never
  `new PrismaClient()` elsewhere.
- Schema lives in `prisma/schema/<owner>.prisma`. Edit only the file of the
  owner you are working on; a module never edits another module's models or
  adds relations to them.
- Create migrations with `pnpm prisma7 migrate dev --create-only --name <owner>_<change>`
  (the v7 CLI owns `prisma/migrations/`; Prisma 8 has no `migrate dev`), then
  add the SQL Prisma cannot express (RLS, exclusion constraints, extensions,
  partial indexes) to the same file before applying it. Afterwards re-emit
  the runtime contract: `pnpm prisma contract infer && pnpm prisma contract emit`.
- Every tenant-owned table: `tenantId`, `@@index([tenantId, ...])`, per-tenant
  uniques, the RLS block from the spec, and a classification entry. Same change.
- Every migration must work with the code currently deployed. Renames, type
  changes, new `NOT NULL` and drops go through expand → migrate → contract
  across deploys. Ask before writing anything that could lose data.
- Large-table indexes are created `CONCURRENTLY`, in a migration of their own.
- Never edit or delete a merged migration. Never `migrate reset` or `db push`
  against a shared database.
- Data fixes on many rows are backfill scripts: idempotent, batched,
  resumable, dry-run by default.
- `src/generated/migrations.ts` is generated by `pnpm build` (prebuild). Do not hand-edit it.
- Scope every query on tenant data (the scoped client does it; do not work around it).
- Select only what you use on hot paths and lists; paginate lists.
- Multiple writes that must succeed together go in one transaction.
- No raw SQL unless Prisma cannot express it; if needed, use tagged
  `$queryRaw` (parameterised), never `$queryRawUnsafe` with interpolated input.
- Money is `Int` cents; time is UTC `DateTime` plus the tenant's IANA time zone.

---

Based on: the Prisma docs on migrations, multi-file schemas and the client (prisma.io/docs), the expand/contract pattern for zero-downtime schema changes, and PostgreSQL row-level security.
